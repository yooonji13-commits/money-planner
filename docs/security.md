# 보안

이 앱은 개인·가족용이며 로그인도 계정도 없다. 아래가 실제로 지키는 선과 **지키지 않는 선**이다.
지키지 않는 것을 분명히 적어 두는 이유는, 그것을 "고쳐야 할 구멍"으로 착각해 사용자가 정한
결정을 되돌리지 않게 하기 위해서다.

## 무엇을 지키는가

지키는 것은 **한 기기에서 개인 탭 화면이 남에게 보이지 않게 하는 것**과, **개인 탭 내용이 파일로
빠져나가지 않게 하는 것** 두 가지다.

지키지 않는 것:

- 기기에 저장된 내용 자체는 **암호화되지 않는다.** 브라우저 개발자 도구나 기기 데이터 접근으로
  읽을 수 있다. 비밀번호는 화면을 가리는 잠금이며 암호가 아니다.
- 6자리 코드를 아는 사람은 누구나 그 가계부를 **읽고 덮어쓸 수 있다.** 서버 쪽 접근 제한이 없다.

## 개인 탭 잠금

### 비밀번호 저장

- 원문을 저장하지 않는다. **SHA-256 해시의 16진 문자열**만 저장한다
  (`crypto.subtle.digest`, `sha256Hex()`).
- 저장 위치는 `localStorage`의 `mp_personal_pw_v1` — **가계부 데이터(`mp_data_v1`) 밖의 별도
  키**다.
- **기기 전용이다.** 클라우드로 보내지 않고, 클라우드에서 받아도 반영하지 않으며, 내보내기
  파일에도 넣지 않는다. 한 기기에서 걸어도 연결된 다른 기기는 잠기지 않는다.
- 예전 형식(가계부 데이터 안에 해시가 들어 있던) 데이터를 읽으면 기기 키로 옮기고 가계부
  데이터에서 지운다. **이 이관 때문에 잠기거나 풀리는 일이 없어야 한다** — 걸려 있던 기기는
  계속 잠겨 있고, 안 걸려 있던 기기는 계속 안 잠겨 있다.
- 백업 파일에 해시가 들어 있어도 **무시한다.** 남의 백업을 가져와도 이 기기의 비밀번호는 그대로다.
- 해제는 저장 키를 지우는 것이다. 되돌릴 수 없다(복구 수단이 없다).

### 잠금이 열리고 닫히는 조건

- 잠긴 상태의 판정은 `personalLocked()` = **비밀번호가 설정돼 있고 아직 풀지 않음**이다. 지금
  어느 탭을 보고 있는지와 무관하다.
- 개인 탭에 잠금 화면이 뜨는 조건은 `onPersonalLockScreen()` = 위 조건 + 개인 탭에 있을 때다.
- **개인 탭을 벗어나면 다시 잠긴다.** 풀린 상태는 세션에만 있고 저장되지 않는다.
- 비밀번호를 설정하면 그 즉시 풀린 상태가 된다(방금 정한 사람이므로).

### 틀린 비밀번호를 넣었을 때

- 4자 이상 치는 동안 맞으면 바로 풀린다(제출 없이). 틀리면 아무 일도 일어나지 않는다.
- 제출하면 틀렸다는 안내가 뜬다. **다시 입력하기 시작하면 안내가 사라진다.**
- **횟수 제한도 대기 시간도 없다.** 무한히 시도할 수 있다. 개인·가족용이라는 판단이며, 기기
  자체가 잠겨 있는 것을 전제로 한다.

### 잠긴 동안 막는 것

| 기능 | 잠긴 동안 | 이유 |
|---|---|---|
| 개인 탭 화면 | 막힘 | 내역이 보이면 안 된다 |
| 내보내기 | 막힘 (예외 없음) | 개인 탭 내용까지 파일로 나간다 |
| 가져오기 | 막힘 (안내 화면에서만 예외) | 데이터를 통째로 덮어쓴다 |
| 고정내역 | 숨김 | 개인 탭 고정내역이 보인다 |
| 동기화 | 허용 | 새 기기에서는 연결부터 해야 하는 경우가 있다 |
| 계산기 | 허용 | 가계부 내용과 무관하다 |

**안내 화면의 예외.** 저장된 원문을 읽지 못해 안내 화면이 뜬 상태에서는 잠금 화면이 나올 자리가
없어 비밀번호를 풀 방법이 없다. 그 상태에서 가져오기까지 막으면 백업 파일로 되살릴 길이 사라져
기기 데이터를 통째로 지우는 것 말고는 방법이 없다. 그래서 그 화면에서만 **가져오기를 열어둔다** —
가져오기는 파일을 집어넣는 동작이라 내용이 밖으로 나가지 않는다. 헤더의 내보내기는 그때도 막고,
대신 안내 화면 자체의 내보내기(`export-storage-raw`)가 원문을 그대로 내려받게 한다.

## 동기화 접근

- 접근 수단은 **6자리 숫자 코드뿐**이다. 코드를 넣으면 그 가계부를 읽고 쓸 수 있다.
- 코드는 `Math.random()`으로 뽑는다(암호학적으로 안전한 난수가 아니다).
- **자리수를 6자리로 유지하는 것은 사용자의 결정이다.** 손으로 입력하는 편의를 택했고, 코드를
  찍어 맞힐 위험은 알고 받아들였다. 늘리지 않는다.
- 새 코드를 발급할 때는 **먼저 그 코드가 이미 쓰이고 있는지 확인**한다. 쓰이고 있으면 다른 코드를
  뽑는다(최대 10회). 확인이 안 되면(인터넷 끊김 등) **아무것도 쓰지 않는다** — 확인되지 않은
  코드로 덮어쓰면 남의 가계부를 지운다.
- 남는 위험: 두 기기가 **같은 순간에** 같은 코드로 확인을 통과하면 나중에 쓴 쪽이 이긴다. 완전히
  막으려면 데이터베이스 쪽 제약이 필요하다.
- 코드로 처음 연결하면 **확인 없이 연결한 기기의 내용이 상대편 내용으로 바뀐다.** 사용자가 정한
  동작이다. 확인 창을 넣지 않는다.

## 외부에 박혀 있는 값

`index.html`에 Supabase 주소와 공개 키(`publishable`)가 그대로 들어 있다. 정적 파일로 배포되므로
숨길 수 없고, 숨기는 것이 목적인 키도 아니다. **다만 이 파일을 공개 저장소에 올리면 누구나 그
프로젝트에 요청을 보낼 수 있다는 뜻**이다. 실제 접근 통제는 Supabase 쪽 설정에 달려 있으며 이
저장소 밖이다.

## 확인 작업을 할 때의 규칙

앱을 브라우저로 띄워 확인할 때 **실제로 쓰고 있는 동기화 코드로 연결해서는 안 된다.** 연결하면
실제 가계부가 확인용 브라우저로 내려오고, 그 뒤 모든 저장이 클라우드로 올라가 **휴대폰의 실제
데이터를 덮어쓴다.** 확인은 직접 넣은 연습용 데이터로만 하고, 동기화 동작을 시험할 때는 클라우드
쪽을 대역으로 바꿔 놓고 한다.

## 기록으로 남기는 것

**아무 것도 남기지 않는다.** 감사 로그가 없다. 누가 언제 무엇을 바꿨는지 추적할 수 없고, 추적할
필요가 없는 규모라는 판단이다. 유일하게 남는 시간 정보는 `mp_last_saved_at`(마지막 저장 시각)과
클라우드 행의 `updated_at`이며, 둘 다 어느 쪽이 최신인지 판단하는 용도다.
