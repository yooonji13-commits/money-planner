# 알아두면 덜 헤매는 것들

## 확인 작업

### `file://`로 열면 저장이 전혀 안 된다

**증상:** 파일을 브라우저로 직접 열어(또는 미리보기 창에 띄워) 값을 넣어도 새로 열면 사라진다.
동기화 화면을 열면 "동기화 기능을 불러오지 못했어요"가 뜬다.

**원인:** `file://`과 `data:` 주소에서는 `localStorage` 접근이 SecurityError로 막힌다. 그러면
저장·불러오기·가져오기·동기화가 모두 동작하지 않고, 저장 실패 안내만 계속 뜬다.

**어떻게:** 반드시 http 주소로 띄운다. `.claude/serve.js`가 저장소 루트를 정적으로 내주는
20줄짜리 서버이고 `.claude/launch.json`에 4173번 포트로 등록돼 있다. 절차는 운영 문서에 있다.

### 값을 넣고 새로고침하면 방금 넣은 값이 사라진다

**증상:** 개발자 도구에서 `localStorage.setItem("mp_data_v1", ...)`으로 확인용 데이터를 넣고
`location.reload()`를 하면, 열린 화면에는 넣은 데이터가 아니라 이전 데이터가 보인다.

**원인:** 앱을 열 때 읽은 내용을 정규화해서 그 자리에 되쓴다(`loadState`). 그래서 새로고침하면
**앱이 메모리에 들고 있던 이전 상태가 방금 넣은 값을 덮어쓴다.** 입력 중이던 값이 있었다면
닫힐 때의 마무리 저장(`flushPendingBeforeLeave`)도 같은 일을 한다.

**어떻게:** 같은 출처의 **앱이 아닌 주소**로 먼저 이동해 거기서 데이터를 넣고, 그다음 앱 주소로
이동한다. 확인용 서버는 없는 경로에 404를 주므로 `http://localhost:4173/__seed` 같은 주소를 쓰면
된다(앱 코드가 실행되지 않으므로 마무리 저장이 일어나지 않는다). 데이터를 넣은 뒤 실제로 들어갔는지
한 번 읽어 확인하고 나서 판단한다.

### 실제 동기화 코드로 연결하면 실제 가계부를 덮어쓴다

**증상:** — (일어나면 되돌릴 수 없다)

**원인:** `index.html`에 실제 Supabase 주소와 키가 박혀 있다. 확인용 브라우저에서 실제 코드로
연결하면 실제 가계부가 내려오고, 그 뒤 저장될 때마다 클라우드로 올라가 **휴대폰의 실제 데이터를
덮어쓴다.**

**어떻게:** 확인 작업에서 실제 코드로 연결하지 않는다. 동기화 동작을 시험해야 하면, CDN
`<script src>` 줄을 지운 사본을 만들고 `window.supabase.createClient`를 대역으로 심어
`.from().select()` / `.upsert()` 호출을 기록하게 한다. 그러면 겹침·인터넷 끊김·쓰기 실패를
마음대로 만들어 볼 수 있고 실제 주소로 요청이 나가지 않는다.

## 화면

### 숫자를 치는데 키패드가 내려간다

**증상:** 아이폰에서 금액을 치다가 키패드가 사라지고 커서가 빠진다.

**원인:** `render()`가 `#mp-main`을 `innerHTML`로 통째로 다시 만든다. 그러면 사용자가 커서를
올려둔 입력칸이 **새 노드로 교체**되어 포커스가 사라진다.

**어떻게:** 값이 바뀔 때 통째로 그리지 않고 그 항목의 부분 갱신 함수를 쓴다
(`updateUtilityDisplay`, `updateLivingDisplay`, `updateSavingsDisplay`,
`updatePersonalBalanceDisplay`, `updateLoanDisplay`, `liveUpdateLoanFromDOM`,
`liveUtilityChartPatch`, `updateFixedItemsTotal`). 실시간 동기화도 같은 이유로, 입력칸에 커서가
있거나 잠금 화면이 떠 있으면 데이터만 반영하고 다시 그리지 않는다.

같은 함정이 잠금 화면에도 있다. 틀린 비밀번호 안내를 지우려고 화면을 다시 그리면 치던 비밀번호가
지워지고 키패드가 내려간다 — 안내 문구 요소만 제거해야 한다.

### 부분 갱신으로 그래프를 바꿀 때 svg를 교체하면 안 된다

**증상:** 실기기에서 관리비 숫자를 치는 중 포커스가 빠진다.

**원인:** 그래프를 `outerHTML`로 갈아끼우면 svg 노드가 교체되고, 그 과정에서 포커스가 빠지는
경우가 있다.

**어떻게:** `liveUtilityChartPatch()`처럼 기존 svg 노드는 그대로 두고 `d` 속성과 좌표·텍스트만
바꾼다.

### 화면 폭이 좁아지면 sticky 요소가 엉뚱한 자리에 붙어 있다

**증상:** 헤더 아래 고정 영역이 내용과 겹쳐 보인다.

**원인:** 아이폰 사파리가 `main.innerHTML` 교체 후 `position: sticky` 위치를 다시 계산하지 않는
경우가 있다.

**어떻게:** `updateStickyOffset()`이 1px 스크롤을 주고 되돌려 재계산을 유도한다. 이상해 보이지만
의도된 우회다. 지우면 증상이 돌아온다.

### `type=number` 입력칸에서 커서 이동이 실패한다

**증상:** 커서를 끝으로 보내려는데 예외가 난다.

**원인:** 일부 브라우저가 `type=number`에서 `setSelectionRange`를 막는다.

**어떻게:** `caretToEnd()`가 `try`로 감싸고 있다. 그리고 사파리는 포커스 직후 탭한 위치로 커서를
되돌리므로 `setTimeout(..., 0)`으로 한 박자 뒤에 옮긴다.

## 데이터

### 정규화 순서를 지켜야 한다 — 달 묶음부터

**증상:** 깨진 데이터를 가져오면 정규화 코드 자체가 오류를 낸다.

**원인:** 달 묶음 자리에 숫자나 문자열이 들어 있으면 지금 코드는 "값이 있다"로 보고 통과시킨다.
그 뒤 `tx`에 속성을 대입하려 하면, `"use strict"` 아래에서 원시값에 속성 대입은 **오류**가 된다.

**어떻게:** `tx`를 손보기 **전에** 달 묶음이 객체인지 먼저 확인하고, 아니면 기본 형태로 교체한다
(`normalizeMonthBuckets`).

### 정렬 기준값이 없는 기록은 0이 아니라 "없음"이어야 한다

**증상:** 같은 날짜 목록의 순서가 이상하다.

**원인:** 정렬 규칙이 "기준값 없음"과 "기준값 0"을 다르게 다룬다. 없는 것은 예전 기록으로 보고
먼저 적힌 것으로 취급한다. 정규화에서 0으로 채워 버리면 이 구분이 사라진다.

**어떻게:** `ts`가 유한한 숫자가 아니면 필드를 **지운다**(0으로 만들지 않는다).

### 계좌 `id`는 중복이어도 다시 발급하면 안 된다

**증상:** 계좌는 남아 있는데 그 계좌의 기록이 전부 사라진다.

**원인:** `state.logs`가 계좌 `id`를 열쇠로 쓴다. 정규화가 중복 `id`를 새로 발급하면 `logs`의
열쇠와 어긋나 기록이 주인을 잃는다.

**어떻게:** 내역 줄의 `id`는 중복 시 다시 발급하지만, **계좌와 대출의 `id`는 없을 때만 발급하고
중복은 건드리지 않는다.**

### 금액이 문자열이면 버리지 말고 숫자로 읽어 본다

**증상:** 백업을 가져오니 금액이 0이 된 기록이 있다.

**원인:** 규칙이 "유한한 숫자가 아니면 0"이라, `"5000"`처럼 숫자로 읽히는 문자열도 0이 될 수 있다.

**어떻게:** 숫자로 읽히는 값은 숫자로 바꾸고, 정말 읽을 수 없는 값(`"abc"`, `NaN`, 객체)만 0으로
한다. 되살릴 수 있는 금액을 0으로 만드는 것은 기록을 지우는 것과 같다.

### 관리비 `payDate`가 숫자면 탭이 깨진다

**증상:** 관리비 탭이 안 그려진다.

**원인:** 날짜 표시 함수가 `.split()`을 부른다. 숫자에는 그 함수가 없다.

**어떻게:** 정규화에서 `payDate`를 문자열로 강제한다.

## 저장

### 저장 실패가 조용히 다음 줄을 건너뛴다

**증상:** 저장 공간이 꽉 찬 기기에서 탭을 눌렀는데 화면이 바뀌지 않는다.

**원인:** `localStorage.setItem`이 던진 예외가 같은 처리 함수를 빠져나가면서, 뒤따르던
`render()`가 실행되지 않는다.

**어떻게:** `writeStorage()`가 예외를 잡고 `notifySaveFailed()`로 알린 뒤 **밖으로 던지지
않는다.** 저장에 실패해도 화면 갱신은 계속 진행된다. 같은 안내가 쏟아지지 않게 10초 간격으로
묶는다.

### 읽기 실패 경로도 감싸야 한다

**증상:** 저장이 막힌 기기에서 아무 동작도 안 된다.

**원인:** `getSyncCode()`가 저장할 때마다 불린다. 읽기가 막힌 상태에서 감싸지 않으면 쓰기와
똑같이 처리가 중단된다.

**어떻게:** 읽기도 `readStorage()`로 감싼다.

### 원문을 읽지 못했을 때 원래 자리를 지우면 안 된다

**증상:** 안내 화면이 한 번 뜨고, 다시 열면 빈 가계부로 정상 시작한다(원문이 사라졌다).

**원인:** 읽지 못한 원문을 다른 키로 "옮기면" 원래 자리가 비고, 다음 실행에서는 읽을 게 없으니
정상적인 첫 실행으로 보인다.

**어떻게:** **복사만 하고 원래 자리는 남긴다.** 복사본이 이미 있으면 덮지 않고 뒤에 번호를 붙여
새 자리를 쓴다 — 원문을 두 번 잃지 않기 위해서다.

## 이월

### 짝 표식과 출처 표식을 한 필드에 섞지 않는다

**증상:** 이월 줄을 지웠는데 엉뚱한 줄이 사라지거나, 이월한 적 없는데 막힌다.

**원인:** `carryFrom`은 "이 줄은 그 달에서 넘어왔다"는 **출처**이고 이월 여부 판단에 쓰인다.
`carryPairId`는 두 줄을 묶는 **짝 표식**이다. 두 용도를 한 필드에 섞으면 한쪽 판단이 다른 쪽을
망친다.

**어떻게:** 두 필드를 따로 둔다. 짝 삭제는 `carryPairId`로, 이월 여부 판단은 `carryFrom`으로 한다.

### 정규화가 새 필드를 지워 버릴 수 있다

**증상:** 이월하고 앱을 새로 열면 짝이 풀려 한쪽만 지워진다.

**원인:** 정규화가 알 수 없는 필드를 떨어뜨리면 짝 표식이 사라진다.

**어떻게:** `normalizeEntry()`는 줄 객체를 제자리에서 손보고 새로 만들지 않으므로 모르는 필드가
그대로 남는다. 짝 표식은 값이 비정상일 때만 지운다. **정규화를 "필요한 필드만 뽑아 새 객체를
만드는" 방식으로 바꾸면 이 성질이 깨진다.**

## 동기화

### 확인되지 않은 코드로 쓰면 남의 가계부가 사라진다

**증상:** — (일어나면 남의 데이터가 사라진다)

**원인:** `upsert`는 같은 코드의 행이 있으면 덮어쓴다. 존재 확인 없이 발급하면 겹친 사람의 가계부가
통째로 교체된다.

**어떻게:** 발급 전에 `isSyncCodeTaken()`으로 확인하고, **확인 자체가 실패하면 쓰지 않는다.**
조회 오류를 "비어 있음"으로 취급하면 안 된다 — 확인 함수가 오류를 그대로 던지게 되어 있다.

### 실시간 갱신이 자기가 올린 것을 되받는다

**증상:** 저장할 때마다 화면이 한 번 더 깜빡인다.

**원인:** 자기가 올린 변경도 실시간 알림으로 되돌아온다.

**어떻게:** 마지막으로 올린 내용의 문자열(`lastPushedSnapshot`)과 비교해 같으면 무시한다. 다만
서버가 항목 순서를 바꿔 돌려주면 문자열이 달라져 비교가 빗나갈 수 있다 — 완벽한 차단은 아니다.

### 앱을 닫으면 마지막 수정이 안 올라간다

**증상:** 한 기기에서 고치고 바로 앱을 닫으면 다른 기기에 반영되지 않는다.

**원인:** 클라우드 전송이 800ms 묶음으로 예약된다. 그 사이에 닫히면 예약이 사라진다.

**어떻게:** `flushCloudPush()`가 대기 시간을 건너뛰고 바로 올린다. `pagehide`에서 부르지만,
아이폰이 페이지를 먼저 죽이면 요청이 못 나갈 수 있다 — 개선이지 보장은 아니다.
