# 주고받는 형식

이 앱은 호출할 수 있는 API를 내놓지 않는다. 다만 밖과 맞물리는 두 가지 형식이 있고, 둘 다
호환을 깨면 사용자의 데이터가 들어오지 못하거나 다른 기기와 어긋난다.

1. **백업 파일** — 내보내기가 만들고 가져오기가 읽는 JSON 파일
2. **클라우드 행** — Supabase `sync_data` 테이블의 한 줄

## 백업 파일

### 내보내기가 만드는 것

파일 이름은 `moneyplanner-backup-YYYY-MM-DD.json`(앱을 연 날짜)이다. 내용은 기기에 저장된
`mp_data_v1` 원문을 **그대로** 내려받는다 — 다시 조립하지 않는다.

안내 화면의 내보내기는 읽지 못한 원문의 사본을 우선 내려받고, 사본이 없으면 원래 자리의 원문을
내려받는다. 즉 **읽을 수 없는 내용도 파일로 건져낼 수 있다.**

**비밀번호 해시는 들어가지 않는다.** 기기 전용 값이라 가계부 데이터 밖에 있다.

### 가져오기가 받아들이는 것

| 단계 | 조건 | 어긋나면 |
|---|---|---|
| 1 | JSON으로 읽힌다 | "파일을 읽을 수 없어요…" — 지금 데이터 유지 |
| 2 | 객체다 (배열·숫자·문자열 아님) | "머니플래너 백업 파일이 아니에요." — 지금 데이터 유지 |
| 3 | `accounts` `logs` `living` `savings` `utilities` `loans` 중 **하나 이상**이 있다 | "머니플래너 백업 파일이 아니에요." — 지금 데이터 유지 |
| 4 | 덮어쓸지 확인 | 취소하면 지금 데이터 유지 |

3단계를 "하나 이상"으로 둔 이유: 일부만 담긴 오래된 백업까지 거절하지 않기 위해서다. 여섯 열쇠가
하나도 없으면 다른 앱의 파일로 본다.

**형식은 맞지만 안의 기록이 깨져 있으면 거절하지 않는다.** 정규화해서 받아들이고, 몇 군데를
보정했는지 알린다. 기록은 버리지 않는다. 멀쩡한 파일에는 이 안내가 뜨지 않는다 — 값이 실제로
있었고 틀렸을 때만 세기 때문이다.

가져오기가 성공하면 `mp_data_v1`을 통째로 바꾸고 페이지를 다시 불러온다. **이 기기의 비밀번호는
바뀌지 않는다** — 파일에 해시가 들어 있어도 무시한다.

### 가계부 데이터의 모양

```
{
  "activeTab":     "personal" | "living" | "family" | "loan" | "utility",
  "currentMonth":  "YYYY-MM",
  "monthByTab":    { "living": "YYYY-MM", "utility": "YYYY-MM", "family": "YYYY-MM" },

  "accounts": [ {
      "id": "문자열(고유)", "name": "문자열", "purpose": "문자열",
      "accountNumber": "문자열", "color": "#RRGGBB",
      "balance": 숫자(음수 가능),
      "fixedExpenses": [ { "id": "문자열", "day": 1~31, "name": "문자열", "amount": 양수 } ]
  } ],

  "logs": { "계좌id": [ {
      "id": "문자열(고유)", "date": "YYYY-MM-DD"|"",
      "memo": "문자열", "amount": 양수, "type": "expense"|"income", "ts": 숫자(없을 수 있음)
  } ] },

  "living":  { "YYYY-MM": { "budget": 양수, "tx": [ 내역줄 ] } },
  "savings": { "YYYY-MM": { "amount": 양수, "interest": 양수, "eventCost": 양수, "tx": [ 내역줄 ] } },
  "utilities": { "YYYY-MM": {
      "payDate": "YYYY-MM-DD"|"",
      "community": 양수, "electricity": 양수, "water": 양수, "heating": 양수, "other": 양수
  } },

  "loans": [ {
      "id": "문자열", "name": "문자열",
      "originalAmount": 양수, "monthlyPayment": 양수,
      "currentInstallment": 0 이상 정수,
      "rate": "문자열", "startDate": "YYYY-MM-DD"|""
  } ],

  "fixedItemsByTab": {
      "personal": [ 고정내역줄 ], "living": [ 고정내역줄 ], "family": [ 고정내역줄 ]
  },

  "savingsExpenses": [ ... ]   ← 아무도 읽지 않는다. 지우지 말고 그대로 통과시킨다
}
```

**내역줄**(생활비·저축): `id`, `date`, `memo`, `amount`, `ts`. 생활비는 `type`을 갖고, 이월로
생긴 줄은 `carryPairId`(짝 표식)와 — 다음 달 줄만 — `carryFrom`(출처 달)을 갖는다. 저축은
`category`(`가족행사`|`일반`)를 갖는다.

**고정내역줄**: `id`, `category`, `name`, `amount`, `note`.

읽어들일 때 모든 줄에 `date`와 `type`을 채워 넣는다. 정렬과 날짜 표시가 이 두 칸을 그대로
쓰기 때문이다. 그래서 고정지출·고정내역·저축 사용 내역처럼 원래 그 칸을 쓰지 않는 줄에도
저장된 모양에는 `date: ""`, `type: "expense"`가 붙는다. 읽는 쪽은 무시하면 된다.

### 형식을 바꿀 때 지켜야 하는 것

- **모르는 칸은 지우지 않는다.** 정규화가 들어온 객체를 제자리에서 손보고 새로 만들지 않기 때문에
  모르는 칸이 살아남는다. "필요한 칸만 뽑아 새 객체를 만드는" 방식으로 바꾸면 이 성질이 깨지고,
  옛 백업이나 새 필드(예: 이월 짝 표식)가 조용히 사라진다.
- **필드를 없앨 때는 예전 값을 읽을 수 있게 남긴다.** 지금 그 예가 `personalPasswordHash`다 —
  상태에서 떼어냈지만, 기기 저장분에 남아 있으면 기기 전용 자리로 옮긴다.
- **버전 번호가 없다.** 구분은 `localStorage` 키 이름(`mp_data_v1`)으로만 한다. 호환을 깨야 하면
  키 이름을 올리고 예전 키에서 옮겨오는 처리를 넣는다.

## 클라우드 행 — Supabase `sync_data`

| 칸 | 무엇 |
|---|---|
| `code` | 6자리 숫자 문자열. 행을 찾는 열쇠 |
| `data` | 가계부 데이터 전체 (위와 같은 모양) |
| `updated_at` | 올린 시각 (ISO 문자열) |

앱이 하는 요청은 세 가지뿐이다.

- **조회** — `select("*").eq("code", 코드).maybeSingle()`
  코드로 연결할 때와 앱을 열 때 쓴다. 새 코드를 발급하기 전 겹침 확인에는 `select("code")`로
  행이 있는지만 본다 — `"*"`로 가져오면 겹침을 확인하는 것만으로 그 코드를 쓰는 사람의 가계부
  전체가 이 기기로 내려온다.
- **쓰기** — `upsert({ code, data, updated_at })`
  같은 코드의 행이 있으면 **덮어쓴다.** 그래서 발급 전 겹침 확인이 필수다.
- **실시간 구독** — 채널 이름 `sync_data_<코드>`, `postgres_changes`에서 `code=eq.<코드>` 필터.

### 어느 쪽이 이기는가

- **앱을 열 때:** 원격의 `updated_at`이 이 기기의 마지막 저장 시각보다 나중이면 원격을 받아
  적용하고, 아니면 이 기기 내용을 올린다.
- **그 뒤부터:** 나중에 쓴 쪽이 이긴다. 두 기기가 같은 시간에 고치면 앞선 수정이 사라진다.
  **의도한 동작이다.**
- **처음 연결할 때:** 확인 없이 연결한 기기의 내용이 상대편 내용으로 바뀐다.

### 받을 때 덮지 않는 것

원격 데이터를 적용할 때 **어느 탭·몇 월을 보고 있는지는 이 기기 값을 유지한다.** 기기별 화면
상태이기 때문이다. 덮으면 다른 기기가 저축 탭에 있을 때 실시간 갱신이 올 때마다 화면이 그쪽으로
튕겨 나간다.

**비밀번호도 원격에서 오지 않는다** — 애초에 올리지 않는다.

### 클라우드 쪽이 없을 때

CDN에서 Supabase 클라이언트를 불러오지 못하면 동기화 기능만 꺼지고 앱은 그대로 동작한다. 동기화
화면에 "동기화 기능을 불러오지 못했어요"가 뜬다.
