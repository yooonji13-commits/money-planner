# 가계부 규칙

이 문서가 앱이 지켜야 하는 계산과 동작의 기준이다. 코드가 이것과 다르면 코드가 틀린 것이다.

## 이름 주의

- 저축 탭의 **내부 이름은 `family`**다(화면에는 "저축"으로 나온다). 이름이 바뀐 흔적이며 코드
  전체에서 `family`를 쓴다. `data-tab="family"`가 저축 탭이다.
- **고정내역**(`fixedItemsByTab`)과 **계좌별 고정지출**(`accounts[].fixedExpenses`)은 **서로
  다른 것**이다. 고정내역은 개인·생활비·저축 탭마다 따로 있는 목록이고, 고정지출은 특정 계좌
  안에 딸린 매달 빠지는 항목이다.
- 생활비 고정내역 맨 위의 **"저축"은 입력 항목이 아니다.** `월급 분류 합계 − 나머지 분류 합계`로
  계산되어 표시되는 값이며, 사용자가 직접 적을 수 없다.

## 탭별 계산

### 개인 — 계좌와 기록

- 계좌는 **기준 잔액**을 갖는다. 기록(`logs[계좌id]`)은 그 위에 쌓인다.
- **총 보유자산 = 기준 잔액 + 모든 입금 − 모든 지출.**
- 기준 잔액은 **음수가 될 수 있다**(마이너스 통장). 음수일 때 빨간 글씨로 보인다.
- 기록의 금액은 **양수만, 0은 안 된다.** 지출인지 입금인지는 `type`이 정한다. 0이나 음수를
  넣으면 저장하지 않고 이전 값으로 되돌린다.

### 생활비 — 달마다 기준 금액

- **이번 달 생활비 = 기준 금액 − 지출 합계 + 입금 합계.**
- 진행바가 채우는 값은 잔액이 아니라 **실제로 쓴 만큼 = 지출 − 입금**(음수면 0으로 본다).
  입금을 빼지 않으면 돈이 남았는데도 다 쓴 것처럼 꽉 차 보인다.
- 진행바 단계: 기준 금액이 0이면 쓴 게 있을 때만 100%. 기준 금액이 있으면 쓴 만큼이 기준을
  넘으면 초과, 아니면 90% 이상 / 75% 이상 / 50% 이상 / 그 밖으로 네 단계.
- **기준 금액은 양수만이다.** 마이너스를 붙여 넣어도 입력칸·화면·저장값 모두 양수가 된다.

### 저축 — 달별 순저축

- **이번 달 순저축 = 저축금액 + 결산이자 + 집안행사비용 − 사용 금액 합계.**
- **집안행사비용은 더한다.** 이름이 비용이라 빼야 할 것처럼 보이지만 더하는 것이 맞다 —
  사용자가 확인한 계산이다. 이것을 "버그"로 보고 빼는 쪽으로 바꾸면 안 된다.
- **총 저축액 = 저장된 모든 달의 순저축 합.**
- 저축금액·결산이자·집안행사비용은 **양수만이다.**
- 사용 내역의 분류는 `가족행사`, `일반` 두 가지다. 저장된 값이 이 둘에 없으면(예전에 다른 값을
  적었으면) 그 값도 선택지에 넣어 그대로 보여준다 — 데이터를 바꾸지 않는다.
- 분류가 없는 사용 내역은 목록의 마지막 분류(`일반`)로 본다.

### 대출

- **변제 금액 = 현재 회차 × 월 상환액**
- **잔여 금액 = 원금 − 변제 금액**
- **총 회차 = 올림(원금 ÷ 월 상환액)**, 월 상환액이 0 이하면 0으로 본다(회차 표시를 숨긴다)
- **잔여 회차 = 총 회차 − 현재 회차**, 음수면 0
- 상환 게이지는 갚은 만큼 채워지고, 다 갚으면 완료 상태가 된다.
- 대출 탭에서는 **잔여 금액이 양수일 때 빨갛다.** 다른 탭과 반대다 — 남은 빚이 많은 것이 나쁜
  값이기 때문이다.
- 원금과 월 상환액은 **양수만**, 현재 회차는 **0 이상 정수**다.

### 관리비

- **최종 관리비 = 커뮤니티 + 전기료 + 수도비 + 난방비 + 기타.** 다섯 항목 모두 양수만이다.
- 값이 실제로 들어간 달(합계가 0보다 큰 달)이 하나라도 있을 때만 월별 변화 그래프가 나타난다.
- 그래프의 가로 범위는 **값이 들어간 달 + 지금 보고 있는 달**로 잡는다. 그냥 넘겨보기만 해서
  생긴 0원짜리 달은 범위에 넣지 않는다. 항목(전기료 등)을 바꿔도 가로 범위는 전체 관리비 기준을
  유지한다 — 항목을 바꿀 때마다 범위가 널뛰지 않게 하기 위해서다.
- 데이터가 몇 달 없어도 추세가 보이도록 최소 6개월 폭은 그린다.

### 고정내역

- 개인·생활비·저축 탭마다 **완전히 분리된 목록**이다. 한 탭에서 추가한 항목이 다른 탭에 보이지
  않는다.
- 분류 선택지: 생활비는 `월급`, `정훈`, `윤지`, `기타`. 저축은 `가족행사`, `일반`. 개인 탭은
  선택지 없이 직접 적는다.
- 생활비 탭에서는 분류별로 묶어서 보여주고, 분류 없는 항목은 `기타` 묶음에 넣는다(데이터의
  분류 값을 바꾸지는 않는다).
- 생활비 합계 표시는 **월급을 제외한 지출만** 더한다. 월급이 섞이면 단순 합계가 의미가 없다.
- 금액은 양수만이다.

## 금액 부호 — 전체 규칙

**마이너스를 넣을 수 있는 칸은 개인 탭 기준 잔액 하나뿐이다.**

| 항목 | 부호 |
|---|---|
| 개인 탭 계좌 기준 잔액 | 음수 허용 (± 버튼으로 뒤집는다) |
| 개인 탭 기록 금액 | 양수만, 0 불가 |
| 생활비 기준 금액 | 양수만 |
| 생활비 내역 금액 | 양수만, 0 불가 |
| 저축 저축금액 · 결산이자 · 집안행사비용 | 양수만 |
| 저축 사용 내역 금액 | 양수만, 0 불가 |
| 관리비 다섯 항목 | 양수만 |
| 고정내역 · 고정지출 금액 | 양수만 |
| 대출 원금 · 월 상환액 | 양수만 |
| 대출 현재 회차 | 0 이상 정수 |

양수만인 칸은 **입력칸 글자 · 입력 중 화면 · 저장값 세 곳이 모두 양수**여야 한다. 한 곳만
양수로 만들면 손을 떼는 순간 값이 튄다.

**이미 저장돼 있는 음수 값은 일괄로 바꾸지 않는다.** 그대로 보여주고, 사용자가 그 칸을 다시
고치는 순간부터 새 규칙이 적용된다.

## 날짜

- 화면 입력 형식은 `YYYY.MM.DD`, 저장 형식은 `YYYY-MM-DD`다.
- 숫자 8자리가 다 채워져야 유효하다. 그보다 짧으면 무효로 보고 **이전 값을 되돌린다** — 저장된
  날짜를 지우지 않는다. 이 규칙은 내역 날짜 세 곳, 관리비 납부일자, 대출 시작일 모두에 적용된다.
- 월은 1–12로 맞춘다. 일은 **그 달의 마지막 날을 넘지 않게** 맞춘다: `2026.02.31` → `2026-02-28`,
  `2028.02.31` → `2028-02-29`, `2026.13.45` → `2026-12-31`.
- 새로 추가하는 양식에서 날짜가 무효면 오늘로 넣는다(되돌릴 이전 값이 없다).
- **날짜는 치는 도중에 저장하지 않는다.** 치는 중간 상태(`2026`, `2026.1`)는 전부 무효라서,
  저장하면 이미 적어둔 날짜가 지워진다.

## 목록 순서

같은 데이터로 두 번 그리면 목록 순서가 **완전히 같아야 한다.**

- 날짜 내림차순(개인 탭은 최신순/과거순 선택 가능)이 우선이다.
- 같은 날짜 안에서는 저장된 순서를 그대로 지킨다(안정 정렬).
- 정렬 기준값(`ts`)이 있는 기록과 없는 기록이 같은 날짜에 섞이면, **없는 쪽을 먼저 적은 것으로
  본다.** 최신순에서는 있는 쪽이 위, 과거순에서는 없는 쪽이 위다.
- **날짜가 빈 기록은 어느 방향에서도 목록 맨 끝**이다.
- 두 값을 뺄셈으로 비교하면 안 된다 — 기준값이 없는 기록에서 결과가 숫자가 아니게 되어 비교
  자체가 망가진다.

## 달 이동

- 생활비·관리비·저축은 달을 오가며 본다. **탭마다 보고 있던 달을 따로 기억한다** — 생활비에서
  8월을 보다 관리비로 가면 관리비는 관리비가 보던 달 그대로다.
- 앱을 완전히 새로 열면 세 탭 모두 **오늘이 든 달**로 돌아간다. 보고 있던 달은 기기별 화면
  상태이므로 동기화되지 않는다.
- 내역의 날짜를 다른 달로 고쳐도 **그 내역은 원래 적었던 달에 그대로 남는다.** 달 묶음이 소속을
  정하고 날짜는 표시일 뿐이다.

## 이월

생활비의 남은 잔액을 다음 달로 넘긴다. **이월은 항상 두 줄이 한 쌍이다.**

- 다음 달에 **1일자 입금 줄**이 들어간다.
- 원래 달에 **같은 금액의 지출 줄(상쇄 줄)**이 들어간다. 그래서 원래 달 잔액이 0원이 된다.
- 두 줄은 같은 `carryPairId` 값으로 묶인다. `carryFrom`은 이와 **다른 필드**로, 다음 달 줄에만
  붙어 "이 줄은 그 달에서 넘어왔다"는 출처를 나타내며 이월 여부 판단에 쓰인다.
- **짝 표식이 있는 줄을 지우면 짝도 같이 사라진다**(다른 달에 있어도). 한쪽만 남는 상태는
  만들어지지 않는다. 지울 때 확인 창이 이 사실을 알린다.
- **짝 표식이 없는 예전 이월 줄은 짝이 없다.** 그 줄을 지우면 그 줄만 사라진다.
- 이월할 잔액이 0원 이하면 알리고 아무것도 만들지 않는다.
- **한 번 이월한 달은 다시 이월할 수 없다** — 상쇄 줄 때문에 잔액이 0원이 되어 "잔액이 없어요"에
  걸린다. 다시 하려면 두 줄 중 하나를 지우면 된다(짝이 사라지고 잔액이 돌아온다). 그래서 두 번
  빠지는 상태는 만들어질 수 없다.
- 예전 형식 기록(다음 달 줄만 있고 상쇄 줄이 없는 경우)에는 "이미 이월했어요" 안내가 계속
  필요하다.
- **원래 달 진행바는 기준 금액이 있으면 꽉 찬다**(상쇄 줄이 지출이므로). 잔액이 0원이라는 사실을
  그대로 보여주는 것이므로 의도된 결과다. 기준 금액을 넘긴 것은 아니므로 초과 색은 아니다.
  기준 금액이 0인 달을 입금으로 생긴 잔액으로 이월하면 진행바는 비어 있는 채로 남는다.

## 개인 탭 잠금

- 비밀번호가 설정돼 있으면 개인 탭에 들어갈 때 잠금 화면이 뜬다.
- **다른 탭으로 갔다 오면 다시 잠긴다.** 풀린 상태는 그 탭에 머무는 동안만 유지된다.
- 비밀번호는 4자 이상이고, 설정·변경 시 두 번 입력해 일치를 확인한다.
- **비밀번호를 풀기 전에는 어느 탭에 있어도 내보내기와 가져오기가 막힌다.** 개인 탭을 벗어나면
  자동으로 다시 잠기므로, 잠금 화면에서만 막으면 탭 하나 눌러 나간 뒤 그대로 내보낼 수 있어
  차단이 무의미하다.
- 동기화와 계산기는 잠긴 동안에도 쓸 수 있다 — 새 기기에서는 연결부터 해야 하는 경우가 있다.
- 예외는 저장된 내용을 읽지 못해 안내 화면이 뜬 상태다. 그때는 내보내기와 가져오기가 모두
  동작한다(그 화면에서는 잠금을 풀 방법이 없고, 막으면 되살릴 길이 사라진다).

## 깨진 데이터를 다루는 규칙

**기록은 절대 지우지 않는다.** 읽을 수 없는 값은 안전한 값으로 바꾸되 줄 자체는 남긴다.

| 필드 | 잘못된 값일 때 |
|---|---|
| `id` | 없으면 새로 발급. 한 목록에 같은 값이 두 번 나오면 뒤에 나온 것에 새로 발급 |
| `date` | `YYYY-MM-DD` 형식이 아니면 빈 문자열 |
| `amount` | 유한한 숫자가 아니면 0. 숫자로 읽히는 문자열(`"5000"`)은 숫자로 바꾼다 |
| `type` | `expense` \| `income` 둘 중 하나가 아니면 `expense` |
| `ts` | 유한한 숫자가 아니면 **필드를 없앤다**(0으로 만들지 않는다 — 정렬 규칙이 "없음"과 "0"을 다르게 다룬다) |
| 글자 필드 | 문자열이 아니면 빈 문자열 |

같은 `id`를 다시 발급하는 이유: 삭제는 같은 `id`를 가진 줄을 **전부** 지우고 편집은 **첫 줄만**
잡는다. 중복이 있으면 한 줄을 지울 때 다른 줄이 함께 사라진다.

**계좌의 `id`는 중복이라도 다시 발급하지 않는다.** `logs`가 계좌 `id`를 열쇠로 쓰기 때문에,
바꾸면 그 계좌의 기록 전체가 주인을 잃는다.

달 묶음 자체가 객체가 아니면(숫자·문자열·`null`) 그 달을 기본 형태로 교체한다. `tx`를 손보기
**전에** 달 묶음이 객체인지 먼저 봐야 한다 — 원시값에 속성을 붙이려 하면 그 자체가 오류가 된다.
