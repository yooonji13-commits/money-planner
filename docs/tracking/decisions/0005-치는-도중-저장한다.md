# 0005 — 금액칸은 치는 도중에 저장하고 저장 버튼을 없앤다

## 상황

관리비 금액을 치는 동안에는 화면 합계만 바뀌고 기기에는 저장되지 않았다. 화면에는 이미 반영돼
있어서 저장된 것처럼 보였고, 그 상태로 앱을 닫으면 방금 친 값이 사라졌다. 고정내역 금액도 같은
경로였다. 관리비 탭에는 저장 버튼이 있었지만, 값은 이미 화면에 들어가 있어 버튼이 무엇을 하는지
불분명했다.

## 결정

관리비 금액 다섯 칸과 고정내역 금액은 **치는 도중에 저장한다.** 관리비 저장 버튼을 없애고, 대신
값이 저장될 때 "저장됨 ✓"을 잠시 보여준다. 앱이 백그라운드로 가거나 닫힐 때는 입력 중이던 값을
마무리 저장하고 클라우드 전송 대기 시간을 건너뛴다.

**날짜칸은 이 대상에서 뺀다.**

## 고르지 않은 것

- **저장 버튼을 남기고 버튼을 눌러야 저장되게 하기** — 언제 저장되는지 명확하다. 버렸다: 사용자가
  버튼을 안 누르고 나가면 값이 사라지는 것이 바로 원래 문제였다.
- **저장 버튼만 남기고 표시는 없애기** — 다른 탭과 일관된다. 사용자가 짧은 표시를 골랐다: 저장이
  됐는지 한눈에 알 수 있는 신호를 원했다.
- **날짜칸도 치는 도중 저장하기** — 일관되어 보인다. 버렸다: 날짜를 치는 중간 상태(`2026`,
  `2026.1`)는 전부 무효로 판정되므로, 저장하면 **이미 적어둔 날짜가 지워진다** — 이번 작업이
  없애려던 사고와 같은 종류다.
- **짧게 묶어서 저장하기(디바운스)** — 키 입력마다 쓰지 않아 부담이 적다. 지금은 넣지 않았다:
  지금 규모에서는 키 입력마다 써도 느껴지지 않고, 묶는 순간 "방금 친 값이 저장됐는가"가 다시
  불확실해진다. 기록이 많아져 입력이 버벅이면 그때 넣는다.

## 결과 / 제약

- **치는 도중 저장할 때 화면을 통째로 다시 그리면 안 된다.** 입력칸 노드가 교체되어 아이폰에서
  키패드가 내려간다. 항목별 부분 갱신 함수를 쓰는 지금 구조가 이 결정의 전제다.
- **키 입력마다 `localStorage`에 쓴다.** 입력 처리에서 `saveState()`를 바로 부른다. 묶어서
  쓰는 장치는 없다 — 넣으려면 그 호출 자리에 넣어야 한다. 기록이 많아지면 쓰는 양도 커진다.
- **닫힐 때의 마무리 저장은 실제로 바뀐 게 있을 때만 한다.** 아무것도 고치지 않고 앱을 넘겼다
  돌아오는 것만으로 저장 시각이 갱신되면, 이 기기가 "가장 최신"으로 표시되어 다른 기기의 더 나중
  수정을 덮어쓸 수 있기 때문이다. 다만 개발자 도구로 저장소에 값을 넣고 새로고침하면 여전히
  이전 상태가 그 값을 덮어쓴다 — 앱을 열 때 읽은 내용을 정규화해 되쓰기 때문이다. 확인 작업 때
  걸려 넘어지기 쉬운 지점이다.
- **닫힐 때의 클라우드 전송은 보장이 아니다.** 아이폰이 페이지를 먼저 죽이면 요청이 못 나간다.
  800ms 대기보다 낫지만 확실하지는 않다.
